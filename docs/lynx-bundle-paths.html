Lynx 4.0 · Bundle Storage

内置 Bundle 与 OTA Bundle，究竟读哪里、存哪里？

当前生产目标：内置 baseline 只读直取，远程 OTA 才写入应用私有磁盘。内置资源不在 App 启动时复制一份。

一句话结论：APK/HAP/App Bundle 里的内置 Bundle 是发布资产；设备私有目录里的 Bundle 是运行时 OTA 缓存。三端读取内置资源时先做 Manifest、size、SHA-256 校验，远程版本才进入 current/previous/staging 事务。

2. 读取与存放流程

① 构建期下载脚本读取全量 API 返回的 App ID、Release 和 Bundle。
② 打包写入 APK assets / iOS App Bundle / Harmony rawfile。
③ 启动原生请求全量 latest-bundle-list，App ID 不由宿主猜测。
④ 远程更新远程 Bundle 写入私有 releases，完整校验后提交 current。
⑤ 页面读取优先读已提交 current；没有 current 才读内置 baseline。

5. current、previous、baseline 的关系

REMOTE OTA

有远程更新

releases/remote-v2/       ← 远程 Bundle
states/10000001.json      ← current = downloaded/remote-v2
                           ← previous = downloaded/remote-v1

远程版本完整下载、size/SHA 校验和原子发布后，才切换 current。

EMBEDDED BASELINE

没有远程 current

APK assets/...             ← 内置 baseline
应用私有磁盘              ← 不生成 embedded 副本
页面直接读取 assets/rawfile

如果远程首屏失败且没有可用 previous，Runtime 丢弃坏的远程 current，回到内置资源。

历史数据说明：旧版本曾经把内置 Bundle 复制到 Android 的 files/lynx-ota-store/embedded，真机上可能还留有旧目录。新代码启动时会清理这类旧副本；当前生产路径不再创建它。

6. 谁负责什么？

组件负责不负责
sync_ota_bundles_to_assets.mjs按 --target 把服务端返回的全量 Bundle 下载到 Android/iOS/Harmony 构建资源，校验 size/SHA。不负责运行时 current，也不写设备私有目录。
LynxOtaRuntime启动/前台全量同步、远程下载、current/previous、回滚。不猜 App ID，不把内置 baseline复制到磁盘。
Tab Container只读取已提交 current 或内置 baseline，切 Tab 不触发网络。不请求 OTA、不决定 App ID。
文档对应仓库：lynx-navigation-to-ota。路径示例基于 Android debug 包 com.example.lynxshell.debug；正式包的 package name 和 filesDir 会随宿主配置变化。
