01 · Priority

你现在最急需做的 Top10

这里的“做”包含接入默认宿主、补齐方法、统一协议和设备验收；已经有源代码的能力，不再重复造一套。

02 · Decision

四个先后判断

这四个判断决定了后续工作是有效收口，还是继续堆没有进入业务链路的接口。

先接通

默认构建图和注册

Capacitor Module 目前是独立能力层。Android、iOS、HarmonyOS 都需要宿主显式加入构建图，并在每个 LynxView 注册。

再收口

权限、回调、销毁

每个能力都要有 permission state、异步结果、取消、前后台变化和 Module destroy 清理，避免状态只在 catalog 里“看起来已实现”。

最后扩展

高级体验和新场景

PiP、后台视频、Widgets、Maps、Speech、Contacts 等放到核心设备能力稳定之后，按真实业务场景增加。

03 · Coverage

三端重点能力矩阵

这是 40 个能力域中的高价值分组；状态来自当前三端 catalog 和 dispatcher/adapter：Native 表示模块内有完整方法实现，Partial 表示存在方法或平台边界，Unsupported 表示明确不支持。

40 个能力域按业务相关性合并展示；源码状态不代表默认 Shell 已接通，也不代替真实设备验收。
能力域AndroidiOSHarmonyOS对 Top10 的关系
注意：HarmonyOS 的 `status()` 已明确区分 `implemented / partial / unsupported`；Android/iOS catalog 中的 partial 同样需要设备权限、系统 Provider、生命周期和错误分支验收。
04 · Roadmap

建议按三批推进

每一批都应该形成可被业务页面调用的闭环，而不是只更新 catalog。

Batch 01 · 接通基础

让已有能力可调用

  • 三端默认注册 `LynxCapacitorModule`。
  • 统一权限状态、回调 envelope 和销毁清理。
  • 完成 Camera、Barcode、MediaPicker、Filesystem、FileTransfer。
  • 先用诊断 Bundle 验证页面调用。
Batch 02 · 业务闭环

覆盖登录、消息和位置

  • LocalNotifications、Push Token、通知点击路由。
  • Secure Storage、Biometrics 的平台差异处理。
  • Deep Link、Browser、OAuth、Share、Clipboard。
  • Foreground Geolocation、Motion、Network。
Batch 03 · 体验增强

补后台和系统级体验

  • Audio 录音/播放和中断恢复。
  • BackgroundRunner 与 OTA/网络恢复联动。
  • Screen Capture、屏幕方向、键盘和系统栏细节。
  • 再按业务需要增加 Maps、Contacts、Calendar、Speech、Widgets。
05 · Avoid duplicate work

已经有的能力，不要再从零做一遍

这些能力的正确动作是“接入默认宿主、补设备验证或补平台差异”，不是重新设计第二套 API。
