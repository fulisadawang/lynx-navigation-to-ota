结论先看

Android 的“内置 → 启动同步 → 下一次冷启动使用 OTA current”已在真机上观察到。首次截图显示 10000001 / r20260823_qc8ffc / 内置 baseline / main.lynx.bundle；等待启动同步完成后重新冷启动，截图显示 10000001 / r20260823_qc8ffc / OTA current / main.lynx.bundle。run-as 核对确认没有生成 files/lynx-ota-store/embedded 副本。
Native Tab Home 与单独打开的 Playground 使用同一个 10000001 + main.lynx.bundle，手机屏幕均显示相同 release/source；切换 Home/Settings 后前台 Activity 仍为 NativeTabDemoActivity，Bundle render 计数没有因切换增加。显式刷新时全量同步计数为 2，两个 Tab 的 main Bundle render 总计为 4，符合“启动一次 + 主动刷新一次”的预期。
2026-08-27 聚焦真机复验确认 candidate 被页面消费后，后台同步不再误报 candidate 发布后不可读取；正常 promote 和首屏故障 discard 均完成，失败场景页面仍可用且稳定 current 未被覆盖。
Store v2 全新安装后，真实服务返回的两个 App ID 分别落在 apps/10000001/... 与 apps/10000002/...；顶层不存在旧 releases/、states/、.staging/。Inspector 显示 44 个真实文件、约 4.5 MB，刷新期间没有 OTA 请求日志。

对 iOS 行为契约的对照

内置 baseline 不复制；服务端响应提供 App ID；current 优先；Tab cache-only；启动/前台全量同步；主动刷新后 Tab 重读；版本卡显示身份。
Android candidate/trial/healthy promote；首屏错误进入一次性 recovery；previous remote 保持 ota_current 来源，embedded 才标 rollback_fallback。
iOS 有 XCUITest；Android 当前是 JVM + adb/真机人工证据，没有 instrumentation runner。
本轮真实服务没有新 release delta，不能验证 releaseId 变化；下一次服务端发布 Android 新版本后，只需重跑 A-02、A-05、A-06、A-07、A-10、A-16。
