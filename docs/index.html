API REFERENCE

Lynx Navigation to OTA

三端统一的原生导航与 OTA 契约

面向 Android、iOS、HarmonyOS 的统一 Bundle 导航与热更新协议。服务端只需要返回可校验的 Release 元数据，客户端负责下载、校验、原子激活和页面加载。

查看 API 契约
1. 应用启动 初始化 Router 与 OTA SDK
2. 请求最新列表 latest-bundle-list
3. 下载 Bundle 直接读取 OSS/CDN
4. 校验完整性 size + SHA-256
5. 设置为 current 交给 LynxView 加载

公共请求约定

            
所有 /api/ota/v1 请求都遵守

          

          

            

              
请求头

              
令牌由原生宿主从安全配置运行时注入，不进入 Lynx 页面和 Bundle。

              
Accept: application/json
x-ota-client-token: <runtime-token>

Content-Type: application/json; charset=utf-8

            

            

              
Base URL

              
API 请求和 OSS/CDN Bundle 下载是两条链路，Bundle 下载不携带 OTA token。

              
API:    https://ota.example.com
Bundle: https://cdn.example.com/.../*.lynx.bundle

            

          

        


        

          

            
Release 数据结构

            
服务端返回的核心快照

          

          

            
            
{
  "env": "TEST",
  "hostApp": "capp",
  "lynxAppId": "10000001",
  "releaseId": "r20260629_001",
  "platform": "android",
  "status": "ACTIVE",
  "changedBundles": [
    {
      "pageId": 10000001,
      "bundlePath": "pages/10000001/home.lynx.bundle",
      "bundleUrl": "https://cdn.example.com/home.lynx.bundle",
      "bundleSha256": "sha256:<64 位小写十六进制>",
      "size": 524288,
      "required": true,
      "prefetch": true
    }
  ]
}

          

          

            
            bundlePath 是精确的 Bundle 身份，服务端不能只返回 bundleName。
              路由调用传入 lynxAppId + bundleName，客户端优先按 bundlePath 精确匹配。
          

        


        

          

            
Bundle 校验规则

            
下载成功不等于可以激活

          

          

            

              
                
字段规则客户端行为

              
              
                
bundlePath相对路径，禁止绝对路径、..、反斜杠和路径穿越精确定位 current Bundle

                
bundleUrl生产必须 HTTPS，返回非空二进制直接请求 OSS/CDN

                
bundleSha256sha256: 加 64 位小写十六进制完整性校验失败则拒绝激活

                
size非负整数，运行时上限 20 MB校验下载字节数

                
required / prefetchBoolean 发布元数据当前 Router 保留字段，不改变打开策略

              
            

          

        


        

          

            
Bundle 下载

            
OSS/CDN 不属于 OTA JSON API

          

          

            
            客户端直接 GET changedBundles[].bundleUrl。不要给 CDN 透传
              x-ota-client-token；服务端无需维护远程 Host 白名单，但客户端仍会校验 HTTPS、2xx、大小和 SHA-256。
          

        


        

          

            
结果上报

            
用于检查、下载、激活、打开和回滚可观测性

          

          

            

              
事件

              
event 支持 check、download、activate、page_open、rollback 五类事件。

              
POST /api/ota/v1/release/report

eventStage:  CHECK | MATCH | MANIFEST
              DOWNLOAD | ACTIVATE
              PAGE_OPEN | ROLLBACK
eventResult: SUCCESS | SKIPPED | FAILED

            

            

              
成功响应

              
服务端接受事件后返回 accepted；Release 不存在时返回 404。

              
{
  "accepted": true,
  "releaseId": "r20260629_001",
  "event": "lynx_release_activate"
}

            

          

        


        

          

            
错误处理

            
失败时优先保留可用版本

          

          

            

              
                
HTTP含义客户端处理

              
              
                
200JSON 成功响应解析并继续事务

                
400请求参数不合法记录错误，保留当前版本

                
401客户端令牌无效或缺失不忙循环重试，交给宿主修正配置

                
404没有可用 Release 或 Manifest继续使用当前/内置 Bundle

                
429请求过于频繁遵守 Retry-After

                
5xx服务端或网络失败有旧包先打开，缺包显示 Loading/失败重试
